## Task 128 — O(n²) → linear-in-structure prune

### Root cause (per closed bar, in `BrcIngestBar`)
1. **Zone-advance loop** — [brc_baysix.mq5:149](../../mt5/Experts/brc_system/brc_baysix.mq5#L149) iterates *all zones ever confirmed* every bar (just tests `alive`). With ~100k zones over 8.5yr × ~850k M5 bars → dominant quadratic term. ~98.6% of zones are dead (invalidated) and re-checked forever.
2. **Break detection** — [BrcDetectBreaksOnBar](../../mt5/Include/brc_system/brc_breakouts.mqh#L36) iterates *all swings ever* every bar (skips broken via `continue`, still touches them). Broken swings never fire again → wasted scans grow unbounded.
3. **Freshness loop** — [brc_zones.mqh:251](../../mt5/Include/brc_system/brc_zones.mqh#L251) scans *all* swings for one strictly in (p3_time, p4_time), per P1 candidate.

(Per-break helpers `BrcSwingUsedInZones` / `BrcZoneDuplicate` / `BrcFirstSwingAfter` / `BrcFindP5ForP1` fire per-break, not per-bar, and the P1 scan already `break`s at `p1_time <= p5_time` — secondary; address only if profiling says so. The newest→oldest P1 window is already bounded.)

### Fix — live-index lists (free-list), all parity-neutral  ✅ BUILT 2026-06-19 (call_id 80, compiles 0err/0warn)
- **Alive-zone index list** per TF: `int alive_idx[]`. Advance loop iterates only `alive_idx`; on death, **order-preserving compaction** out (NOT swap-remove). Equivalent to the `alive` test the code already does → byte-identical, but O(alive) not O(all-ever).
- **Unbroken-swing index list** per TF: `int live_sw[]`. `BrcDetectBreaksOnBar` iterates only `live_sw`; on break, compacted out. **⚠️ Deviation from original plan: ONE combined list, NOT type-segregated.** Type-segregation would reorder cross-type breaks within a bar, and break-append order drives zone-confirm order → CSV row order → would fail the byte-identical diff. (Same-type order is preserved either way; opposite-dir zones never dedup-interact, but they share row order.)
- **⚠️ Deviation 2: order-preserving compaction, NOT swap-remove.** Swap-remove is O(1) but scrambles chronological order → also breaks the diff. Compaction is O(live) (same cost as the scan) and keeps order.
- **Freshness loop bound:** swings are chronological → the latest swing strictly before P4 (`last_before_p4`, computed once/break) dominates the open interval (p3,p4); `interrupted = last_before_p4.time > p3_time`. O(1) per P1 candidate, result identical.

### Parity contract (acceptance test, HARD)
- Re-run the 1yr smoke (Open prices only). MUST emit **exactly 12,489 zones**, per-TF counts identical to run #2, and the CSV must diff-clean against run #2's CSV (modulo `zone_id` if Task 127's `zone_key` lands in the same pass — see below).
- If even one zone differs, the prune touched logic — revert and re-derive. No "close enough."

### Out of scope (explicitly)
- No `InpHistoricalBars`-style window cap (would drop long-span zones → breaks the contract; and the cap isn't a strategy rule).
- No change to detection geometry, dedup rules, or lifecycle math.

## Task 127 — overlapping-zone consolidation (flag, don't delete)

- Live EA runs `ConsolidateOverlappingZones` (50%-overlap, keep-biggest) — the "last dedup" BRC lacks.
- **Decision: emit ALL zones; add `is_primary` (1/0) + `consolidated_into` (zone_key of the survivor, blank if primary).** Port the 50%-overlap rule from Sigma, apply at OnDeinit (or post-confirm), mark losers — never drop rows.
- Rationale: keeps the oracle maximal (raw population auditable) AND lets Python get both the parity-faithful traded set (`is_primary=1`) and the clean funnel set (overlaps double-count continuation → inflate base rates in task 120). Reversible.
- New CSV columns: `is_primary`, `consolidated_into`. Ingest (task 119, [tester.py](../../research/code/tester.py)) + `tester_zones` schema (migration 03x) extend to carry them.

## Rider — stable zone identity (answers "which zone is which")  — DECISION: seq + zone_key BOTH (locked 2026-06-19, call_id 80)
- Current `zone_id` is a throwaway OnDeinit counter ([brc_baysix.mq5:242](../../mt5/Experts/brc_system/brc_baysix.mq5#L242)) — reorder/recount shifts every id; carries no TF/identity meaning.
- **`seq`** = per-TF, 1-based, p4_time order = the **human/chart** identity (printed `#seq` on the zone label so chart ↔ CSV tie out). Chart-friendly but fragile as a cross-run join key (population shifts renumber it).
- **`zone_key = {tf}|{dir}|{p4_time}` (append `|{l2}` on same-bar collision)** = the **machine** join key: stable across re-runs, self-describing. This is the join key for funnel results (task 120) and the cross-TF russian-doll reference (low-TF zone → high-TF zone alive at its p4_time).
- Both ship together; `seq` for eyes, `zone_key` for joins. Keep the int `zone_id` as a compact surrogate, ordered by p4_time so it's deterministic.
- Lands naturally in the same CSV-schema touch as Task 127.
