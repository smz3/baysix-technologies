# Protocol 4.0 — "Lean Gates" (design-of-record)

_Date: 2026-06-22 · Author: Syafiq + Claude (design session 2026-06-22 Morning + this rebuild session)_
_Status: **SETTLED — design-of-record.** Supersedes Protocol 3.2 (generic gating) and 3.3 (LdP/Carver/AQR infra consolidation). Those specs → archive on the Phase-4 doc pass._

> **One line:** 7 gates → 4. Strip the front-loaded academic machinery (DSR/PSR/CSCV/PBO, N_trials ledger, t-stat auto-kills) that rejected real-but-underpowered edges "for no reason." A good strategy is three reads: smooth equity curve, acceptable drawdown, holds under cost + walk-forward + Monte Carlo. MT5 emits the ledger; Python only analyses it.

---

## 1. Why (the reframe)

- We over-engineered at the very start — imported López de Prado / Carver / AQR institutional machinery before looking at the simplicity of the whole process. Gates felt like they killed ideas for no reason.
- Most real kills (IB-001, ORB-001) died on **cost** or **look-ahead**, not significance. The heavy in-sample stats earned little and rejected real-but-underpowered/sliced edges.
- OOS / walk-forward persistence is a **direct, simpler luck-test** than an in-sample t-stat.
- See [simplicity_first_protocol](../../memory) (steer) + [no_cross_model_priors](../../memory) (only oracle-vetted data for the active idea).

## 2. Definition of a good strategy (the 3 criteria)

A good strategy, in 7yr-trader terms, is just three reads:
- **(a) smooth equity curve** — not a volatile path to the result.
- **(b) acceptable drawdown.**
- **(c) holds up** when cost + walk-forward + Monte Carlo are added.

Diagnostic loop when it fails: **bad curve → tune signal/entry params · high DD → tune sizing/exits.**

## 3. The 4 gates

| Gate | Name | What it asks | Pass bar | No code? |
|---|---|---|---|---|
| **G1** | Premise | Idea + one simple rule + thesis + **a linked research paper** (directly or indirectly related). Why should this edge exist? | Sensible mechanism + a falsifiable thesis + ≥1 `step2_papers` row. Tag `idea_kind` + `output_type` here. | No code |
| **G2** | Edge & Survival | Build the rule; emit the **IS net-of-cost** ledger. Is the equity curve smooth + DD acceptable? | Curve eyeball + DD read (criteria a+b). The IS tuning loop lives here. | EA emits ledger |
| **G3** | Robustness | Does the IS edge survive **walk-forward + Monte Carlo**? (Cost already in from G2.) | OOS/WF persistence + MC trade-shuffle survival (criterion c). The anti-luck/anti-overfit test. | analysis only |
| **G4** | Live | MT5 tester EA → demo → live parity. | Demo/live ledger matches tester within tolerance. | EA live |

- **t-stat is NOT an auto-kill.** It may be *reported beside* the curve, never blocks. Inherited academic orthodoxy — removed. Replaced by OOS/WF persistence as the luck-test.
- **Kill stays human + ≥2-falsified** (rule 8b): a single falsified hypothesis is a reframe trigger, not a kill.
- **Cost is in from the first edge number** (G2 net, and OOS net). No separate cost gate.
- **The old Gate-7 FIDELITY gap dissolves** — there is no Python→MQL5 port to reconcile (MT5 *is* the engine), so port-fidelity is replaced by G4 demo/live parity.

## 4. MT5-native architecture

- **The EA emits the ledger inside the MT5 Strategy Tester** — causal, bar-by-bar, no look-ahead (the OnBar event structurally kills the argmax-by-position look-ahead that manufactured the old ORB "edge").
- **Python is the analysis layer only** — PnL + stats on the emitted ledger. It never simulates fills or reconstructs trades.
- **Venue = asset class:** CFD / FX / high-leverage → **MT5** (wire now). Equity / ETF → **IBKR** (design seam only, defer).

## 5. Metrics stack (settled 2026-06-22)

The unit of measurement is **a trade (an event), not a calendar day** — we are event-driven, not a daily-rebalanced portfolio. Forcing the ledger into a daily series injects a flat-day artifact unrelated to the edge. So:

1. **MT5 tester report → decides.** Native, ground-truth: trade list + equity curve + Sharpe / profit factor / max DD / recovery factor / expected payoff. Parsed by [ingest_tester_report.py](../../research/code). This is the G2 edge+DD read with zero reconstruction.
2. **empyrical → our-convention per-trade stat** the report lacks (per-trade Sharpe with **T = trade count**, matching [per_period_sharpe_units_rule](../../memory) — per-period × √T, no √252). Thin wrapper, no daily paradigm.
3. **QuantStats-lumi → decorates only.** The pretty tearsheet for *looking* at a run; its annualized Sharpe (calendar artifact) **never** drives a gate decision. Pinned version.
4. **Monte Carlo + Walk-forward → bespoke**, on the trade list (no library ships them; they're specific to our trade-sequence unit). MC = shuffle/block-bootstrap the trade sequence; WF = rolling re-test windows. These are the G3 build.
5. **Frequency is its own visible number** — trades/year, avg holding time, % time in market — reported beside the metrics, never baked into an annualized Sharpe.

**Hierarchy in one line:** *MT5 decides, empyrical adds our-convention number, QuantStats decorates, MC/WF are the only real build.*

## 6. IS run numbering (replaces DSR / N_trials)

- DSR / PSR / CSCV / PBO / `trial_family` ledger → **dropped.**
- Replaced by per-idea **IS run numbering** (IS-01, IS-02…): an `is_run` label on result rows + a tiny `is_runs` table (`idea_id, label, what_changed, created_at`).
- Its real job isn't "best Sharpe" — it is **counting how many shots were taken** before G3 (the only honest deflator left). The G2 tuning loop logs each tune as an `is_run` so the degrees of freedom stay visible.
- Query e.g. "BRC — which IS run gave best Sharpe/Sortino, and how many runs preceded it?"

## 7. Tester-from-IDE / headless CLI (VERIFIED 2026-06-22)

- **Mechanism:** `terminal64.exe /config:<abs path>\tester.ini` with a `[Tester]` block (`Expert / Symbol / Period / Model / FromDate / ToDate / Report / ShutdownTerminal`) runs **headless**, writes the report → parse via `ingest_tester_report.py`. The `MetaTrader5` Python pkg does **not** expose the tester; this CLI is the bridge.
- **Gotcha:** the terminal must be **closed** for `/config` to take.
- **Smoke-test evidence (this session):** [mt5/tester/brc_smoke.ini](../../mt5/tester/brc_smoke.ini) launched `brc_baysix` on `XAUUSD.s` M5, Open-prices-only, 1 month. Log: `init OK — 8 TFs` → `done — 1092 zones across 8 TFs`, `Test passed in 0:00:00.518`, terminal self-closed. Report `brc_smoke_report.htm` + charts emitted, no errors.
- **History caveat:** JM broker history on `XAUUSD.s` only reaches **2025-01-02**. Full-history IS emit runs on the **custom Dukascopy symbol** (`XAUUSD_dukas` / `XAUUSD_pq` in the JM terminal); `XAUUSD.s` is for recent / live-parity only. (Confirms [d0_feed_drift_reframe](../../memory): broker history is weak, Dukascopy is the real backtest source.)
- **Model:** emitter uses **Open-prices-only** (Model=2) — detection + invalidation are close-only, so each bar's OHLC is final at close; exact here and far faster than real-ticks (see [brc_emitter_open_prices_model](../../memory)).
